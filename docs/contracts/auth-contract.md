# Auth Contract

## JWT Token

### How it is sent

Every protected request must include the token in the Authorization header:

```text
Authorization: Bearer <token>
```

### Token payload

```json
{
  "userId": "usr_abc123",
  "email": "user@email.com",
  "rol": "ADMIN",
  "exp": 1234567890
}
```

### Role values

| Value | Description |
|---|---|
| `ADMIN` | Full access — users, stores, products, reports |
| `OPERADOR` | Inventory and order management |
| `CLIENTE` | Own cart and own orders only |

## Endpoints

### POST /auth/register

Creates a new user. No token required.

**Request:**

```json
{
  "email": "user@email.com",
  "password": "securepassword123",
  "nombre": "Juan Pérez",
  "rol": "CLIENTE"
}
```

**Response 201:**

```json
{
  "userId": "usr_abc123",
  "email": "user@email.com",
  "nombre": "Juan Pérez",
  "rol": "CLIENTE",
  "activo": true,
  "createdAt": "2026-06-26T00:00:00Z"
}
```

### POST /auth/login

Returns a JWT token. No token required.

**Request:**

```json
{
  "email": "user@email.com",
  "password": "securepassword123"
}
```

**Response 200:**

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "userId": "usr_abc123",
  "rol": "ADMIN",
  "expiresIn": 3600
}
```

**Response 401 — wrong credentials:**

```json
{
  "error": "UNAUTHORIZED",
  "message": "Invalid email or password",
  "statusCode": 401
}
```

### GET /users

Returns all users. ADMIN only.

**Response 200:**

```json
{
  "users": [
    {
      "userId": "usr_abc123",
      "email": "user@email.com",
      "nombre": "Juan Pérez",
      "rol": "CLIENTE",
      "activo": true,
      "createdAt": "2026-06-26T00:00:00Z"
    }
  ]
}
```

### GET /users/{userId}

Returns a single user. ADMIN only.

**Response 200:**

```json
{
  "userId": "usr_abc123",
  "email": "user@email.com",
  "nombre": "Juan Pérez",
  "rol": "CLIENTE",
  "activo": true,
  "createdAt": "2026-06-26T00:00:00Z"
}
```

**Response 404:**

```json
{
  "error": "NOT_FOUND",
  "message": "User not found",
  "statusCode": 404
}
```

### PUT /users/{userId}

Updates user data. ADMIN only.

**Request:**

```json
{
  "nombre": "Juan Carlos Pérez",
  "rol": "OPERADOR"
}
```

**Response 200:**

```json
{
  "userId": "usr_abc123",
  "nombre": "Juan Carlos Pérez",
  "rol": "OPERADOR",
  "updatedAt": "2026-06-26T00:00:00Z"
}
```

### DELETE /users/{userId}

Deactivates a user (soft delete). ADMIN only.

**Response 200:**

```json
{
  "userId": "usr_abc123",
  "activo": false,
  "updatedAt": "2026-06-26T00:00:00Z"
}
```

## Lambda Authorizer behavior

The shared Lambda Authorizer runs before every protected endpoint.

| Condition | Response |
|---|---|
| No Authorization header | `401 Unauthorized` |
| Invalid or expired token | `401 Unauthorized` |
| Valid token, wrong role | `403 Forbidden` |
| Valid token, correct role | Request passes through |

## Unified error format

All services use this exact structure for errors:

```json
{
  "error": "ERROR_CODE",
  "message": "Human readable description",
  "statusCode": 400
}
```

### Error codes

| Code | HTTP Status | When |
|---|---|---|
| `UNAUTHORIZED` | 401 | Missing or invalid token |
| `FORBIDDEN` | 403 | Valid token but insufficient role |
| `NOT_FOUND` | 404 | Resource does not exist |
| `VALIDATION_ERROR` | 400 | Missing or invalid fields |
| `INTERNAL_ERROR` | 500 | Unexpected server error |

## Audit records generated by Auth

Every relevant action writes to the `audit` DynamoDB table:

```json
{
  "auditId": "aud_abc123",
  "usuario": "usr_admin01",
  "accion": "CREAR_USUARIO",
  "fecha": "2026-06-26T00:00:00Z",
  "resultado": "EXITOSO"
}
```

### Audit action values for Auth

| Action | Trigger |
|---|---|
| `CREAR_USUARIO` | POST /auth/register |
| `DESACTIVAR_USUARIO` | DELETE /users/{userId} |
| `ACTUALIZAR_USUARIO` | PUT /users/{userId} |
